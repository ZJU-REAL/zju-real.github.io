EasySteer: A Unified Framework for High-Performance and Extensible LLM Steering

激活干预在推理时调整模型的隐藏状态，无需重新训练即可改变模型行为。EasySteer 将其作为推理服务的一项功能：干预向量内置于 vLLM，按请求挂载，仅损失少量吞吐量。

要点

干预向量是模型隐藏状态空间中的一个方向，对应“更开朗”“拒绝回答”“停止反复自我怀疑”等行为，可在模型生成时加到残差流上，无需修改权重即可改变模型行为。这一思路并不复杂，但以往的实现方式是为 Hugging Face 模型添加钩子，且只能逐条处理请求。

EasySteer 是一个开源框架，将激活干预集成到 vLLM 中。干预向量可通过 CAA、PCA、线性探针、稀疏自编码器特征等分析方法提取，也可通过 LoReFT、LM-Steer 等方法训练得到；随后在 vLLM 优化后的推理引擎中施加，每个请求可分别指定作用层、作用 token、干预强度以及多个向量的组合方式。框架还提供八个应用领域的示例向量和一个 Web 演示系统。

在全部 28 层施加干预时，批量吞吐量保持在 vLLM 的 87.7%–93.5%；在长序列批量推理中，EasySteer 比 pyreft 快 10.8 倍，比 repeng 快 22.3 倍。用于抑制过度思考时，激活干预使 GSM8K 上的推理 token 减少 40%，同时提高准确率；用于缓解幻觉时，PCA 干预使 Llama-3.1-8B 的 TruthfulQA 选择题准确率提高 12.1 个百分点。

1激活干预的工程挑战

微调通过修改权重改变模型行为，成本高，且可能使模型遗忘已有知识；提示词成本低，但效果无法保证。激活干预介于两者之间。根据线性表示假说，许多概念在隐藏状态空间中表现为方向：在某一层的隐藏状态上加上 α·v 可增强对应概念，减去则可抑制该概念。已有研究利用思维模式向量抑制数学推理中的过度思考，利用偏好训练得到的向量控制人设，并利用单一方向开启或关闭模型的拒答行为。

难点在于工程实现。激活干预需要修改前向计算，现有框架为此在 Hugging Face 模型外部添加包装器和钩子。这类框架速度较慢，其中 EasyEdit2 完全不支持批量推理；同时缺少 token 级控制和多向量控制，也难以扩展新算法。

2EasySteer 的设计

EasySteer 包含两个核心模块：生成干预向量的模块，以及在 vLLM 中施加干预的模块；此外还提供资源库和演示系统。图 1 展示了一个向量从提取到生成干预后回复的完整过程。

干预向量的生成

分析类方法从数据中寻找方向。给定体现某一概念的文本和不体现该概念的文本，对比激活加法（CAA，亦称 DiffMean）取两组隐藏状态均值之差；PCA 取成对或中心化激活的主要变化方向，并调整符号使其指向该概念；线性探针训练分类器区分两组文本，取其权重向量。这些方法所需的隐藏状态由 EasySteer 直接通过 vLLM 采集。向量也可来自稀疏自编码器：在 Neuronpedia 的特征描述中检索目标概念，选定特征后取解码器中对应的列向量。

学习类方法冻结模型参数，在任务数据上训练一个小型函数，包括有监督训练的加性向量 h + b、LM-Steer 的线性映射 h + εWh，以及 LoReFT 的低秩编辑 h + Rᵀ(Wh + b − Rh)，后者仅有 2rd + r 个参数。EasySteer 为此重构了 pyreft。

在 vLLM 中施加干预

EasySteer 不修改各模型的具体实现，而是维护一份解码层类名注册表，在模型加载时包装这些层。包装器截获每层输出，执行干预算法，再以原有数据结构返回，因此无需改动模型代码即可适用于不同架构，包括视觉语言模型。干预算法统一实现 BaseSteerVectorAlgorithm 接口，并通过装饰器注册；除添加向量外，该接口还可读取和修改混合专家（MoE）模型的路由 logits。

干预控制粒度细。每个请求可以指定作用层、提示词 token 或生成 token、位置或窗口；文档中的当前版本还支持由特定 token id 触发干预。单次前向计算中可同时施加多个向量和算法，作用范围重叠时按冲突规则处理，即按优先级选择或依次叠加。干预配置按内容缓存，不同配置的请求可共享同一批次；KV 缓存的键包含干预配置，因此施加干预与未施加干预的请求不会共享缓存块。

八个应用领域与演示系统

资源库涵盖安全、推理、知识、真实性、语言、情感、人格和风格八个应用领域，示例向量分布在仓库的复现代码和演示中。基于 Vue 和 Flask 的 Web 演示系统将推理、对话、向量提取和训练集成在同一界面中，并将基线输出与干预后输出并列展示。图 2 给出每个领域的一个示例。

3速度与开销

实验在单张 NVIDIA A6000 上完成，模型为 DeepSeek-R1-Distill-Qwen-1.5B，提示词取自 MATH。干预向量均取零值，以保证各设置生成的 token 数相同，且向量作用于每个 token 位置。EasySteer 使用 vLLM 的连续批处理，其他框架使用显存允许的最大固定批大小。

干预开销较小。干预全部层时，短输出的批量吞吐量下降 12.3%，长输出下降 6.5%；3 个向量同时作用于全部层时，长输出吞吐量仍为原生 vLLM 的 90.6%。单请求延迟仅小幅上升，全部层干预时首 token 延迟由 45.3 ms 增至 51.0 ms。

与现有框架相比，速度差距达到一个数量级。在长序列批量推理中，EasySteer 的吞吐量为 7,074 tokens/s，pyreft 为 653，repeng 为 317，EasySteer 分别快 10.8 倍和 22.3 倍。即使逐条处理请求，其解码速度也约为其他框架的 1.6 至 2 倍。

4干预效果

抑制过度思考

实验参照 SEAL，从 1,000 条 MATH 训练样本中提取三个向量，分别对应执行、反思和转换三类推理步骤；在每个推理步骤的分界处，即 \n\n token 处，加上执行向量并减去另外两个向量。该实验在单个请求中使用了 EasySteer 的 token 触发与多向量控制功能。

在 1.5B 模型上，激活干预将 GSM8K 准确率从 79.6% 提高到 82.3%，同时 token 数由 2,435 降至 1,460，减少 40%；MATH500 准确率从 70.8% 提高到 78.4%。7B 模型在两个基准上分别节省 13.3% 和 16.8% 的 token，GSM8K 准确率由 90.3% 略降至 88.5%，MATH500 准确率由 86.6% 提高到 88.2%。

缓解幻觉

TruthfulQA 实验采用二折交叉验证，比较三种分析类方法和两种学习类方法：前者在最后一个 token 处对比真实回答与幻觉回答，后者在问答数据上训练。

各方法只需修改一个参数即可替换，因此此类对比的成本很低。在 Llama-3.1-8B 上，PCA 将选择题准确率从 50.55% 提高到 62.67%；在 Qwen2.5-1.5B 上，LoReFT 将开放式问答准确率从 27.17% 提高到 33.41%。两类方法的取舍同样明显：分析类方法保持了流畅度，学习类方法则以较低的流畅度得分换取更高的准确率。

5使用方法

EasySteer 采用 Apache-2.0 许可证。当前版本基于 vLLM 0.29.0，支持连续批处理、前缀缓存和 CUDA Graph。与论文相比，请求 API 已有调整：SteeringSpec 取代了论文中的 SteerVectorRequest，token 选择移至 ApplySpec。最简示例如下：

from vllm import LLM, SamplingParams
from vllm.steer_vectors import SteeringSpec, VectorSpec, ApplySpec

llm = LLM(model="Qwen/Qwen2.5-1.5B-Instruct",
          enable_steer_vector=True, steer_algorithms=["direct"])
spec = SteeringSpec(vectors=[VectorSpec(
    source="vectors/happy_diffmean.gguf", scale=2.0,
    layers=list(range(10, 24)),
    apply=ApplySpec(prompt="all", generation="all"))])
out = llm.generate(prompt, steering=spec,
                   sampling_params=SamplingParams(temperature=0.0, max_tokens=128))

使用 vllm serve … --enable-steer-vector 启动 OpenAI 兼容服务后，可将同一 spec 作为每个请求的 steering 字段发送。单向量干预现已可在 vLLM 的 CUDA Graph 中运行；在仓库自带的 v0.29 基准测试中，使用 RTX A6000 和同一 1.5B 模型，全部层干预的吞吐量损失约为 3%。仓库还以 notebook 形式复现了十六篇已发表的激活干预论文，涵盖拒答方向、推理时干预、SEAL、面向视觉语言模型幻觉的 SHARP 以及面向专家路由的 SteerMoE 等。激活干预具有两用性：EasySteer 定位为构建更安全、更可控模型的研究工具，使用其改变模型行为时应向用户披露。
