博客2026 年 11 月 17 日大模型激活干预 · 推理系统阅读约 12 分钟

EasySteer：高性能、可扩展的统一大模型激活干预框架

激活干预在推理时小幅调整语言模型的隐藏状态，以此改变模型行为，不需要重新训练。EasySteer 把它做成了推理服务的一项功能：干预向量直接集成在 vLLM 中，按请求挂载，吞吐量只损失一小部分。

概要

干预向量是模型隐藏状态空间里的一个方向，比如“更开心”“拒绝”“别再自我怀疑”，在模型生成时加到残差流上，不改权重就能改变模型行为。想法很简单，但真要跑起来，过去只能给 Hugging Face 模型挂钩子，一次处理一个请求。

EasySteer 是一个开源框架，把激活干预集成进了 vLLM。干预向量可以用 CAA、PCA、线性探针、稀疏自编码器特征等分析类方法提取，也可以用 LoReFT、LM-Steer 等方法训练得到，再放到 vLLM 优化过的推理引擎里施加。每个请求都能单独指定作用于哪些层、哪些 token、强度多大，以及多个向量怎样组合。框架还提供八个应用领域的示例向量和一个 Web 演示界面。

在全部 28 层上施加干预向量时，批量吞吐量仍有 vLLM 的 87.7% 到 93.5%；长序列批量推理时，EasySteer 的速度是 pyreft 的 10.8 倍、repeng 的 22.3 倍。用于缓解过度思考时，激活干预让 GSM8K 上的推理 token 减少 40%，准确率还有所提高；用于缓解幻觉时，PCA 干预把 Llama-3.1-8B 在 TruthfulQA 选择题上的准确率提高了 12.1 个百分点。

1激活干预为什么需要系统支持

微调靠修改权重来改变模型行为，成本高，还可能抹掉模型原有的知识。写提示词成本低，但效果没有保证。激活干预介于两者之间：按照线性表示假说，很多概念在隐藏状态空间中对应某个方向，在某一层的隐藏状态上加上 α·v 就能强化这个概念，减去则会抑制它。思维模式向量可以抑制数学题上的过度思考，偏好训练得到的向量可以控制人设，单个方向就能开关模型的拒答行为。

难点在于落地。激活干预要改动前向计算，现有框架的做法是给 Hugging Face 模型套上包装器和钩子。这些框架速度慢（EasyEdit2 根本不支持批量推理），缺少 token 级和多向量控制，也很难扩展新算法。

2EasySteer 的工作方式

EasySteer 有两个核心模块：一个生成干预向量，一个在 vLLM 内施加干预；此外还有资源库和演示系统。图 1 展示了一个向量从提取到产出干预后回复的全过程。

生成干预向量

分析类方法从数据中找方向。给定体现某个概念的文本和不体现它的文本：对比激活加法（CAA，也叫 DiffMean）取两组平均隐藏状态之差；PCA 取成对激活或中心化激活的主要变化方向，再调整符号，让它指向这个概念；线性探针训练一个区分两组文本的分类器，取它的权重向量。这些方法所需的隐藏状态，EasySteer 直接用 vLLM 采集。向量也可以来自稀疏自编码器：在 Neuronpedia 的特征描述里搜索想要的概念，选定一个特征，取解码器中对应的那一列。

学习类方法冻结模型，在任务数据上训练一个小函数：可以是有监督训练的加性向量 h + b，LM-Steer 的线性映射 h + εWh，或者 LoReFT 的低秩编辑 h + Rᵀ(Wh + b − Rh)，后者只有 2rd + r 个参数。EasySteer 重构了 pyreft 来支持这条路线。

在 vLLM 中施加干预

EasySteer 没有逐个修改模型实现，而是维护一份解码层类名的注册表，在模型加载时把这些层包装起来。包装器拦截每一层的输出，执行干预算法，再按原来的数据结构返回，所以不改模型代码就能适配各种架构，包括视觉语言模型。所有算法都实现同一个接口 BaseSteerVectorAlgorithm，并用装饰器注册；除了加向量，这个接口还能读取和修改混合专家模型的路由 logits。

控制粒度很细。一个请求可以指定具体的层、提示词 token 或生成 token、位置或窗口；按文档中的当前版本，还可以由特定的 token id 触发。同一次前向计算里可以同时作用多个向量和算法，重叠的部分按冲突规则（优先级或依次叠加）处理。干预配置按内容缓存，不同配置的请求可以放在同一批次里；KV 缓存的键包含干预配置，所以干预和未干预的请求不会共用缓存块。

八个领域与演示系统

资源库覆盖八个应用领域：安全、推理、知识、真实性、语言、情感、人格和风格，示例向量分散在仓库的复现和演示代码里。基于 Vue 和 Flask 的 Web 演示把推理、对话、向量提取和训练放在同一个界面中，基线输出和干预后的输出并排显示。图 2 每个领域各给出一个例子。

3速度

我们在单张 NVIDIA A6000 上测试，模型为 DeepSeek-R1-Distill-Qwen-1.5B，提示词取自 MATH。干预使用全零向量，保证各设置生成的 token 数相同，向量作用于每个 token 位置。EasySteer 使用 vLLM 的连续批处理；其他框架使用显存能容纳的最大固定批大小。

干预的开销很小。所有层都施加干预时，短输出的批量吞吐量下降 12.3%，长输出下降 6.5%；3 个向量同时作用于所有层时，长输出吞吐量仍有原生 vLLM 的 90.6%。单请求延迟也只略有上升：首 token 延迟从 45.3 ms 增加到全部层干预时的 51.0 ms。

和现有框架相比，差距在一个数量级。长序列批量推理时，EasySteer 达到 7,074 tokens/s，pyreft 为 653，repeng 为 317，EasySteer 的速度分别是两者的 10.8 倍和 22.3 倍。即使一次只处理一个请求，EasySteer 的解码速度也是其他框架的约 1.6 到 2 倍。

4效果如何

减少过度思考

我们参照 SEAL，从 1,000 条 MATH 训练样本中提取三个向量，分别对应执行、反思和转换三类推理步骤；在每个推理步骤的边界（\n\n token）加上执行向量，同时减去另外两个。这用到了 EasySteer 的 token 触发和多向量控制，全部在单个请求内完成。

在 1.5B 模型上，激活干预把 GSM8K 准确率从 79.6% 提高到 82.3%，同时 token 数减少 40%（2,435 → 1,460）；MATH500 准确率从 70.8% 提高到 78.4%。7B 模型在两个基准上分别节省 13.3% 和 16.8% 的 token；GSM8K 准确率从 90.3% 小幅降到 88.5%，MATH500 则从 86.6% 升到 88.2%。

减少幻觉

在 TruthfulQA 上，我们用二折交叉验证比较三种分析类方法和两种学习类方法。分析类方法在最后一个 token 处对比真实回答与幻觉回答，学习类方法在问答数据上训练。

每种方法只需改一个参数就能换上，做这类对比的成本很低。在 Llama-3.1-8B 上，PCA 把选择题准确率从 50.55% 提高到 62.67%；在 Qwen2.5-1.5B 上，LoReFT 把开放式问答准确率从 27.17% 提高到 33.41%。两类方法的取舍也看得出来：分析类方法能保持流畅度，学习类方法提高了准确率，代价是流畅度得分下降。

5上手使用

EasySteer 采用 Apache-2.0 许可证。当前版本基于 vLLM 0.29.0，支持连续批处理、前缀缓存和 CUDA Graph。论文发表后，请求 API 有所调整：SteeringSpec 取代了论文中的 SteerVectorRequest，token 选择放在 ApplySpec 里。最小示例如下：

from vllm import LLM, SamplingParams
from vllm.steer_vectors import SteeringSpec, VectorSpec, ApplySpec

llm = LLM(model="Qwen/Qwen2.5-1.5B-Instruct",
          enable_steer_vector=True, steer_algorithms=["direct"])
spec = SteeringSpec(vectors=[VectorSpec(
    source="vectors/happy_diffmean.gguf", scale=2.0,
    layers=list(range(10, 24)),
    apply=ApplySpec(prompt="all", generation="all"))])
out = llm.generate(prompt, steering=spec,
                   sampling_params=SamplingParams(temperature=0.0, max_tokens=128))

同样的 spec 也可以发给用 vllm serve … --enable-steer-vector 启动的 OpenAI 兼容服务，放在每个请求的 steering 字段里。单向量干预现在可以在 vLLM 的 CUDA Graph 内运行；在仓库自带的 v0.29 基准测试中（RTX A6000，同一个 1.5B 模型），全部层干预的吞吐量开销约 3%。仓库还以 notebook 形式复现了十六篇已发表的激活干预论文，从拒答方向、推理时干预，到 SEAL、针对视觉语言幻觉的 SHARP 和用于专家路由的 SteerMoE。激活干预具有两用性：EasySteer 是为构建更安全、更可控的模型而开发的研究工具，用它改变模型行为时，应当告知用户。
